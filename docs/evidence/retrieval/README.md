## 골든셋

- 두 기술 각 7개 사실 × 한국어·영어 = **28문항**. 접근 방식·실험 조건·수치·한계를 고루 담았다.
- 정답은 사실마다 원문 그대로의 **anchor 문구**를 담은 청크 전부다(설계서 §4 — 겹침으로 같은 근거가
  두 청크에 있으면 둘 다 정답, 1~2개/문항). 사람이 눈으로 고르지 않고 문구로 고정했으므로 누구나
  검증할 수 있고, 코퍼스·청킹이 바뀌면 `--label` 로 다시 만든다.
- 검색 범위는 papers_core + 기술 필터(역할 필터 없음)다.

## 결과 1 — 가장 큰 변수는 검색 방식이 아니라 PDF 추출이었다

처음 잰 dense 기준선은 Hit@5 0.43, ITME는 0.29였다. 원인은 2단 학회 논문(ITME·PIM-CXL·InfiniGen)의
추출 텍스트였다.

| 원문 | 공백 비율 | 20자 이상 붙은 단어/청크 |
|---|---|---|
| turboquant-paper (1단) | 13.3% | 1.1 |
| itme-paper (2단) | **2.6%** | **14.4** |
| pim-cxl-paper (2단) | 2.6% | 11.6 |
| infinigen-paper (2단) | 4.9% | 12.1 |

- `pdfplumber` 기본 `x_tolerance=3` 이 좁은 자간에서 공백을 지웠다(`ITMEachievesuptoa35.7%`).
- 2단 페이지를 통째로 읽어 왼쪽·오른쪽 단의 줄이 번갈아 섞였다.

`src/rag/index.py` 를 고쳤다 — `x_tolerance=1.5`, 가운데 선을 가로지르는 단어가 2% 미만인 페이지는
단마다 따로 읽는다. 운영 코드를 바꾸기 전에 세 변형을 같은 골든셋으로 쟀다.

| Hit@5 (MRR@5) | 기본 추출 | x_tol=1.5 | + 2단 분리 (적용) |
|---|---|---|---|
| dense 전체 | 0.43 (0.28) | 0.61 (0.38) | **0.68 (0.38)** |
| dense ITME | 0.29 (0.16) | 0.57 (0.37) | **0.71 (0.37)** |
| dense TurboQuant | 0.57 | 0.64 | 0.64 |
| bm25 전체 | 0.36 | 0.64 | 0.71 |
| rrf 전체 | 0.39 | 0.61 | 0.75 |

TurboQuant(1단)는 2단 분리 전후가 같다 — 휴리스틱이 1단 논문을 건드리지 않는다. 청크 수 638 → 603.

**영향:** 모든 `chunk_id` 가 바뀌었다. `docs/evidence/baseline`·`improved` 의 실행 기록은 옛 색인의
ID를 가리키므로, 그 기록에 `eval/numeric_guard_eval.py --index` 를 쓰면 색인 전문 대신 기록의 quote로
대조한다(기준선 quote는 300자로 잘려 있다). 그 README의 수치는 수정 전 색인으로 잰 값이다.

## 결과 2 — dense vs BM25 vs RRF (수정된 색인)

| Hit@5 / MRR@5 | n | dense | bm25 | rrf |
|---|---|---|---|---|
| 전체 | 28 | 0.68 / 0.38 | 0.71 / **0.52** | **0.75** / 0.48 |
| ko | 14 | 0.57 / 0.27 | 0.50 / 0.30 | **0.64** / 0.37 |
| en | 14 | 0.79 / 0.48 | **0.93 / 0.74** | 0.86 / 0.59 |
| TurboQuant | 14 | 0.64 / 0.38 | 0.71 / 0.42 | **0.79** / 0.46 |
| ITME | 14 | 0.71 / 0.37 | 0.71 / **0.62** | 0.71 / 0.50 |
| Hit@1 전체 | 28 | 0.14 | **0.43** | 0.32 |
| 한·영 완전 회수@5 (사실 14) | | 7 | 7 | 8 |

**셀당 n=7~14다. 경향으로만 읽는다** (설계서 §4, `MIN_N=12` 미만 셀은 스크립트가 경고한다).

- **dense는 찾되 순위가 낮다.** Hit@3과 Hit@5가 같고(0.68) Hit@1은 0.14다. 정답이 대개 2~3위에 온다.
- **영어 원문에 한국어로 물으면 약하다.** dense ko 0.57 vs en 0.79. dense가 놓친 9문항 중 6문항이
  한국어이고, 공통점은 전문 용어(회전·스칼라 양자화기·잔차·비편향·DPU)다. BM25 ko(0.50)는 용어집
  (`src/rag/query_kw.py`)에 없는 단어를 번역하지 못해 더 약하다.
- **영어 질의에서는 BM25가 강하다** (en Hit@5 0.93, Hit@1 0.64). 원문 어휘를 그대로 쓰기 때문이다.
- **RRF는 전체·ko에서 가장 높지만 차이가 작다** — dense 대비 Hit@5 +2문항(0.68 → 0.75).

### 결정

- **운영 검색은 dense 단일로 둔다.** RRF의 이득은 28문항 중 2문항이고 ITME에서는 차이가 없다.
  interface ②의 "측정 근거가 생기면 도입"을 충족한다고 보기엔 표본이 작다. 문항을 늘려 같은 경향이면 도입한다.
- 한국어 질의 약점은 용어집 확장(BM25 축) 또는 질의를 영어로도 함께 던지는 방식이 후보다. 모두 미측정.
